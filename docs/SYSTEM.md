## 1. نظرة عامة

نظام ويب داخلي لإدارة أكاديمية الذكاء الاصطناعي الدولية. يستخدمه الموظفون فقط (عدد قليل، أقل من 10 أشخاص). الطلاب **لا** يدخلون النظام؛ هم سجلات في قاعدة البيانات يضيفها الموظفون.

**وظيفتا النظام الأساسيتان:**

1. **حفظ بيانات الطلاب** وتسجيلهم في الدورات ومتابعة رسومهم ودفعاتهم.
2. **تحضير الدورات** (الحضور والغياب) من قبل المدربين، من الجوال بسهولة.

**ما يحتويه النظام:**

| القسم | الوظيفة |
|---|---|
| الطلاب | قاعدة بيانات الطلاب، بحث، إضافة، تعديل، عرض الدورات والمتبقي على كل طالب |
| الدورات | إنشاء دورة، تحديد المدرب وعدد الأيام وأيام الأسبوع وتواريخها، السعر بالعملتين |
| تفاصيل الدورة | الطلاب المسجلون، الرسوم والدفعات، التحضير اليومي، كشف الحضور، الكشوفات |
| المنتجات | المنتجات بسعرين ومخزون، وتسجيل المبيعات |
| المستخدمون | حسابات الموظفين وصلاحياتهم (للإدارة فقط) |
| الإعدادات | اسم الأكاديمية وبيانات رأس الكشوفات وطرق الدفع والعملة الافتراضية |
| حسابي | بيانات الموظف وتغيير كلمة المرور |

**ما ليس في النظام (حُذف عمدا بطلب الإدارة):** الشهادات، العملاء (CRM)، الاستشارات، الخدمات، المحادثات، الذكاء الاصطناعي، النسخ الاحتياطي إلى Google Drive، سجل التدقيق. الهدف نظام بسيط بلا حشو.

## 3. التقنيات المستخدمة ولماذا

| التقنية | الاستخدام | سبب الاختيار |
|---|---|---|
| **React 19** + **TypeScript** | الواجهة | الأكثر انتشارا، وأي مبرمج يعرفها، والأنواع تمنع الأخطاء |
| **Vite 6** | البناء والتشغيل المحلي | سريع وبسيط |
| **Tailwind CSS 4** | التنسيق | تنسيق مباشر داخل الكود بدون ملفات CSS كثيرة |
| **Firebase Authentication** | تسجيل الدخول | مجاني، ولا يحتاج خادما |
| **Cloud Firestore** | قاعدة البيانات | مجانية ضمن حدود، تتزامن لحظيا بين الأجهزة، وتعمل مؤقتا بدون إنترنت |
| **Firebase Hosting** | الاستضافة | رابط `.web.app` مجاني مع HTTPS |
| **xlsx (SheetJS)** | ملفات Excel | يكتب ملفات Excel حقيقية من المتصفح، مع اتجاه من اليمين لليسار |
| **jsPDF** + **html2canvas-pro** | ملفات PDF | يرسم الكشف كصفحة HTML ثم يحولها إلى PDF، فيظهر الخط العربي صحيحا تماما |

**لا يوجد خادم (Backend) ولا Cloud Functions.** كل شيء يعمل في المتصفح ويتصل مباشرة بـ Firebase. هذا ما يسمح بالبقاء على الخطة المجانية. الحماية مطبقة عبر قواعد Firestore على خوادم Google، فلا يمكن لأحد تجاوزها من المتصفح.

## 4. كيف يعمل النظام (البنية)

```
 ┌───────────────────────────┐
 │  متصفح الموظف / جوال     │
 │  (React - ملفات ثابتة)    │
 └───────┬───────────┬───────┘
         │           │
  تسجيل الدخول    قراءة/كتابة البيانات (لحظي)
         │           │
 ┌───────▼───┐ ┌─────▼──────────────────────┐
 │ Firebase  │ │ Cloud Firestore            │
 │ Auth      │ │ + firestore.rules (الحماية)│
 └───────────┘ └────────────────────────────┘

 Firebase Hosting: يخدم الملفات الثابتة فقط (HTML/JS/CSS/الصور)
```

**مبادئ مهمة في التصميم:**

1. **الواجهة لا تُؤتمن على الصلاحيات.** إخفاء زر عن السكرتير مثلا مجرد راحة في الاستخدام؛ المنع الحقيقي في `firestore.rules`. لو حاول أحد الكتابة مباشرة سيُرفض من الخادم.
2. **البيانات لحظية.** كل صفحة تشترك (onSnapshot) في البيانات التي تحتاجها، فأي تعديل من موظف يظهر فورا عند الآخرين بدون تحديث الصفحة.
3. **الاشتراك مرة واحدة لكل استعلام.** الملف `src/lib/store.ts` يجعل كل استعلام يُفتح مرة واحدة في الجلسة ويتشاركه كل من يحتاجه، لتقليل عدد القراءات (مهم للخطة المجانية). عند تسجيل الخروج تُغلق كل الاشتراكات.
4. **إعادة المحاولة التلقائية.** إذا فشل اشتراك (انقطاع إنترنت، أو لحظة إنشاء الحساب الأول) يعيد المحاولة تلقائيا حتى 6 مرات بفواصل متزايدة.
5. **ذاكرة محلية.** Firestore يحفظ نسخة في المتصفح (IndexedDB)، فالصفحات تفتح بسرعة، والكتابة أثناء انقطاع قصير تُرسل عند عودة الاتصال.
6. **فصل المال عن الأسماء.** تسجيل الطالب في الدورة (`enrollments`) منفصل عن حسابه المالي (`accounts`)، حتى يرى المدرب أسماء طلابه دون أن يستطيع قراءة أي مبالغ.

**التنقل بين الصفحات** يتم عبر الرابط بعد علامة `#`، مثل:
- `#/` الرئيسية
- `#/students` الطلاب
- `#/courses` الدورات
- `#/courses/<معرف الدورة>` تفاصيل دورة
- `#/products`، `#/users`، `#/settings`، `#/account`

لذلك تحديث الصفحة أو مشاركة الرابط يفتح نفس المكان.

## 6. قاعدة البيانات بالتفصيل

Firestore قاعدة بيانات من نوع "مستندات": مجموعات (Collections) تحتوي مستندات (Documents)، وكل مستند له معرف وحقول. التعريفات الكاملة في `src/lib/types.ts`.

**التواريخ** تُخزن نصا بصيغة `YYYY-MM-DD` (مثل `2026-11-24`)، والأوقات الكاملة بصيغة ISO (مثل `2026-11-24T15:00:00.000Z`).

### 6.1 `users` الموظفون

معرف المستند = معرف المستخدم في Firebase Auth (uid).

| الحقل | النوع | الوصف |
|---|---|---|
| `name` | نص | الاسم |
| `username` | نص | اسم الدخول (إنجليزي صغير) |
| `role` | نص | `admin` / `deputy` / `registrar` / `secretary` / `trainer` |
| `active` | منطقي | `false` = موقوف لا يستطيع الدخول ولا القراءة |
| `phone` | نص | اختياري |
| `createdAt` / `updatedAt` | نص ISO | |

### 6.2 `students` الطلاب

| الحقل | الوصف |
|---|---|
| `name` | الاسم الكامل (إلزامي) |
| `phone`، `whatsapp` | الجوال والواتساب |
| `gender` | ذكر / أنثى |
| `city` | المدينة |
| `idNumber` | رقم الهوية |
| `qualification` | المؤهل / الوظيفة |
| `notes` | ملاحظات |
| `createdAt`، `createdBy`، `updatedAt` | متى ومن أضافه |

### 6.3 `courses` الدورات

| الحقل | الوصف |
|---|---|
| `name` | اسم الدورة |
| `trainerId`، `trainerName` | المدرب (معرف حسابه واسمه). فارغ = بدون مدرب |
| `mode` | حضوري / أونلاين |
| `location` | المكان أو رابط القاعة |
| `time` | الوقت نصا (مثل: 5:00 م - 8:00 م) |
| `startDate` | تاريخ البداية |
| `daysCount` | عدد الأيام |
| `weekdays` | أيام الأسبوع المختارة كأرقام: 0 الأحد ... 6 السبت |
| `sessionDates` | ★ قائمة تواريخ أيام الدورة الفعلية (اليوم 1 = أول عنصر). هي المرجع للتحضير |
| `priceSAR`، `priceYER` | السعر بالريال السعودي واليمني (تحدده الإدارة) |
| `seats` | عدد المقاعد (0 = غير محدد) |
| `status` | `open` التسجيل مفتوح / `running` جارية / `done` منتهية / `cancelled` ملغاة |
| `notes`، `createdAt`، `updatedAt` | |

### 6.4 `enrollments` تسجيل طالب في دورة (بدون مال)

| الحقل | الوصف |
|---|---|
| `courseId`، `courseName` | الدورة |
| `studentId`، `studentName`، `studentPhone` | الطالب (الاسم والجوال منسوخان هنا حتى يراهما المدرب دون قراءة مجموعة الطلاب) |
| `trainerId` | مدرب الدورة (منسوخ هنا لتطبيق صلاحية المدرب) |
| `createdAt`، `createdBy` | |

**النسخ (Denormalization):** الاسم والجوال ومعرف المدرب مكررة عمدا. الكود يحدّثها تلقائيا:
- عند تعديل بيانات طالب: تتحدث في كل تسجيلاته (`saveStudent`).
- عند تعديل اسم الدورة أو مدربها: تتحدث في كل تسجيلاتها وسجلات حضورها (`saveCourse`).

### 6.5 `accounts` الحساب المالي (لا يراه المدرب)

**معرف المستند = نفس معرف التسجيل** في `enrollments`، فالربط بينهما مباشر.

| الحقل | الوصف |
|---|---|
| `courseId`، `studentId` | |
| `currency` | `SAR` أو `YER` |
| `price` | السعر المتفق عليه (يبدأ من سعر الدورة ويمكن تعديله) |
| `discount` | الخصم |
| `payments` | قائمة الدفعات، كل دفعة: `amount` المبلغ، `date` التاريخ، `method` طريقة الدفع، `by` الموظف، `note` ملاحظة/رقم حوالة |
| `updatedAt` | |

**الحساب:** المستحق = السعر − الخصم. المدفوع = مجموع الدفعات. المتبقي = المستحق − المدفوع (الدالة `accountTotals` في `format.ts`).

### 6.6 `attendance` الحضور

**مستند واحد لكل يوم من أيام الدورة**، معرفه `<معرف الدورة>_<رقم اليوم>` مثل `abc123_3`.

| الحقل | الوصف |
|---|---|
| `courseId`، `trainerId` | |
| `day` | رقم اليوم (1، 2، 3...) |
| `date` | تاريخ اليوم |
| `marks` | خريطة: معرف الطالب ← الحالة. `P` حاضر، `A` غائب، `L` متأخر، `E` بعذر |
| `updatedAt`، `updatedBy` | |

لماذا مستند لكل يوم وليس لكل طالب؟ لأن قراءة كشف دورة كاملة تكون بعدد الأيام (مثلا 5 قراءات) وليس بعدد الطلاب × الأيام، وهذا يوفر في حدود الخطة المجانية.

**نسبة الحضور** = (حاضر + متأخر) ÷ عدد الأيام التي سُجل فيها حضور الطالب. الأيام التي لم تُحضّر لا تدخل في النسبة.

### 6.7 `products` و `sales`

**products:** `name`، `priceSAR`، `priceYER`، `stock` (المتوفر)، `notes`.

**sales:** `productId`، `productName`، `buyer` (اسم المشتري نصا)، `qty`، `currency`، `unitPrice`، `total`، `paid`، `method`، `date`، `by`، `createdAt`.
عند البيع ينقص المخزون تلقائيا، وعند حذف عملية بيع يرجع.

### 6.8 `settings/main` الإعدادات

## 8. قواعد الحماية firestore.rules

ملخص منطق الملف:

- **كل شيء ممنوع افتراضيا**، ثم تُفتح كل مجموعة بشروطها.
- `active()`: المستخدم مسجل دخول، وله مستند في `users`، و`active == true`. الموظف الموقوف يُمنع من كل شيء فورا.
- دوال الأدوار: `isAdmin`، `isManager` (إدارة + نائب)، `canCourses` (+ مسؤول التسجيل)، `isStaff` (+ السكرتير)، `isTrainer`.
- **المدرب** يقرأ الدورة أو التسجيل أو الحضور فقط إذا كان `trainerId` فيها يساوي معرفه، ويكتب الحضور فقط إذا كانت الدورة دورته فعلا (يُتحقق من مستند الدورة نفسه).
- **السكرتير** يستطيع تعديل المنتج فقط في حقلي `stock` و`updatedAt` (لإنقاص المخزون عند البيع)، ولا يستطيع تغيير السعر.
- **المستخدم** يستطيع تعديل اسمه وجواله فقط في ملفه، ولا يستطيع تغيير دوره أو تفعيل نفسه.
- **الإعداد الأول:** يُسمح بإنشاء أول مدير فقط إذا لم يكن `meta/setup` موجودا، وفي نفس العملية يُنشأ `meta/setup`، فلا تتكرر.

تم اختبار القواعد آليا (18 اختبارا): المدرب لا يقرأ الطلاب ولا الحسابات ولا دورات غيره ولا يرفع صلاحيته، والسكرتير لا يحذف ولا ينشئ دورات ولا مستخدمين ولا يعدل الإعدادات.

**أي تعديل على `firestore.rules` لا يسري إلا بعد النشر** (`npm run deploy` أو `firebase deploy --only firestore:rules`).

## 9. تسجيل الدخول والحسابات

- الدخول باسم مستخدم وكلمة مرور. Firebase يتطلب بريدا، فالنظام يحول اسم المستخدم إلى بريد داخلي وهمي:
  `ahmed` ← `ahmed@users.intai-academy.app`
  لا يُرسل إلى هذا البريد شيء ولا يحتاج أن يكون حقيقيا. (الدالة `usernameToEmail` في `firebase.ts`). **لا تغيّر `USER_DOMAIN` بعد بدء الاستخدام** وإلا لن تعمل الحسابات الحالية.
- اسم المستخدم: أحرف إنجليزية صغيرة وأرقام و `. _ -`، من 3 إلى 30 حرفا. كلمة المرور 6 أحرف على الأقل.
- **الإعداد الأول:** أول من يفتح النظام وقاعدة البيانات فارغة يرى شاشة إنشاء حساب الإدارة.
- **إضافة موظف:** الإدارة تنشئ الحساب من صفحة المستخدمين. تقنيا يُستخدم "تطبيق Firebase ثانوي" (`secondaryApp`) لإنشاء الحساب حتى لا يُسجَّل خروج المدير، ثم يُكتب ملف الموظف في `users`.
- **إيقاف موظف:** يجعل `active = false`، فيُمنع فورا من الدخول ومن قراءة أي بيانات. هذا بديل الحذف.
- **تغيير كلمة المرور:** الموظف يغيرها بنفسه من "حسابي" (يُطلب منه كلمة المرور الحالية).

## 11. سير العمليات خطوة بخطوة

**إنشاء دورة** (`CourseForm.tsx` ← `saveCourse`):
1. الاسم، المدرب، الحالة، النوع، المكان، الوقت، المقاعد، السعر بالعملتين.
2. تاريخ البداية + عدد الأيام + أيام الأسبوع ← تتولد التواريخ تلقائيا (`generateDates`). الافتراضي: السبت إلى الأربعاء.
3. يمكن تعديل أي تاريخ يدويا قبل الحفظ.

**تسجيل طالب** (`EnrollModal.tsx` ← `enrollStudent`):
1. اختيار طالب موجود بالبحث، أو "طالب جديد" يفتح نموذج الإضافة ثم يُختار تلقائيا.
2. اختيار العملة ← يظهر سعر الدورة بتلك العملة، ويمكن تعديله، وإضافة خصم ودفعة أولى.
3. يُنشأ مستند `enrollments` ومستند `accounts` بنفس المعرف في عملية واحدة. يُمنع تسجيل نفس الطالب مرتين في نفس الدورة.

**الدفعات** (`AccountModal.tsx` ← `saveAccount`): زر "الدفعات" بجانب الطالب. تعديل العملة/السعر/الخصم، تسجيل دفعة، حذف دفعة (للإدارة ونائب المدير).

**التحضير** (`CourseDetail.tsx` ← `TakeAttendance` ← `setMarks`):
1. يُختار تلقائيا يوم اليوم إن كان من أيام الدورة، وإلا أقرب يوم قادم.
2. أمام كل طالب 4 أزرار. كل ضغطة تُحفظ فورا. الضغط على الحالة المختارة مرة أخرى يلغيها.
3. "تحضير الباقين حاضرين" يضع "حاضر" لمن لم يُحضّر فقط، ولا يغيّر من سُجلت حالته.
4. الأيام التي فيها تحضير تظهر عليها علامة ✓.

**حذف دورة:** يحذف معها كل تسجيلاتها وحساباتها وسجل حضورها (بعد تأكيد).
**حذف طالب:** ممنوع إذا كان مسجلا في أي دورة؛ يجب إزالته من الدورات أولا (حماية للسجل المالي).

## 12. التصدير PDF وExcel

كل الكشوفات تمر عبر `src/lib/exporter.ts` بنفس الشكل (`Report`): عنوان، سطور معلومات، رؤوس أعمدة، صفوف.

| الكشف | المكان | المحتوى |
|---|---|---|
| كشف الطلاب | صفحة الطلاب | كل الطلاب وبياناتهم وعدد دوراتهم |
| كشف أسماء الدورة | الدورة ← الكشوفات | الأسماء والجوال وعمود توقيع |
| كشف الحضور والغياب | الدورة ← كشف الحضور / الكشوفات | جدول الأيام بالرموز ح/غ/م/ع ملونة، والحضور والغياب والنسبة |
| الكشف المالي | الدورة ← الكشوفات | السعر والخصم والمستحق والمدفوع والمتبقي، وإجماليات كل عملة |
| المنتجات / المبيعات | صفحة المنتجات | |

**PDF:** يبني صفحات A4 بـ HTML (رأس فيه الشعار واسم الأكاديمية والتواصل وتاريخ الإصدار، ثم الجدول، ثم ترقيم الصفحات)، ويوزع الصفوف على الصفحات تلقائيا، ثم يحول كل صفحة لصورة عالية الدقة داخل PDF. كشف الحضور يصبح أفقيا تلقائيا إذا زادت الأيام عن 6. ملاحظة: النص في PDF صورة، فلا يمكن نسخه أو البحث فيه، لكن العربية تظهر صحيحة 100%.

**Excel:** ورقة باتجاه من اليمين لليسار، ورأس فيه اسم الأكاديمية والعنوان والمعلومات، وفلتر على الأعمدة، والأرقام أرقام حقيقية يمكن جمعها.

اسم الملف يُبنى من نوع الكشف واسم الدورة.

## 19. القيود المعروفة

1. **لا يمكن للإدارة تغيير كلمة مرور موظف آخر من داخل النظام** (يحتاج خادما غير متوفر في الخطة المجانية). البديل: إيقاف الحساب وإنشاء حساب جديد، أو من Firebase Console ← Authentication حذف الحساب ثم إنشاؤه من النظام بنفس اسم المستخدم (بعد حذف ملفه القديم من Firestore ← users).
2. **لا يمكن حذف حساب موظف من داخل النظام**، فقط إيقافه (نفس السبب).
3. **لا يوجد نسخ احتياطي تلقائي** (التصدير المُدار يحتاج خطة Blaze). انظر القسم 22.
4. **لا يوجد سجل تعديلات تفصيلي** (من عدّل ماذا ومتى)، باستثناء حقول `createdBy`، و`by` في الدفعات، و`updatedBy` في الحضور.
5. **نص PDF صورة** لا يمكن البحث فيه.
6. **العمل بدون إنترنت** محدود: يمكن التحضير أثناء انقطاع قصير وتُرسل البيانات عند عودة الاتصال، لكن تسجيل الدخول يحتاج إنترنت.
7. **التحقق من الحقول** يتم في الواجهة أساسا؛ القواعد تتحقق من الصلاحيات وليس من صحة كل قيمة.

## 21. نقل النظام إلى حساب أو مشروع آخر

**نقل الكود:** الكود كله في GitHub. يمكن نقل المستودع لحساب آخر من GitHub ← Settings ← Transfer، أو نسخه.

**نقل إلى مشروع Firebase جديد (حساب آخر):**
1. أنشئ مشروعا جديدا وفعّل Email/Password وFirestore (القسم في README).
2. ضع قيم المشروع الجديد في `src/lib/firebaseConfig.ts` ومعرفه في `.firebaserc`.
3. `firebase login` بالحساب الجديد ثم `npm run deploy`.
4. **البيانات لا تنتقل تلقائيا.** خيارات نقلها:
   - إذا كانت البيانات قليلة: أعد إدخالها، أو صدّر الكشوفات Excel للرجوع إليها.
   - نقل كامل: يحتاج تفعيل خطة Blaze مؤقتا على المشروعين واستخدام `gcloud firestore export` ثم `import` عبر Cloud Storage (التكلفة عادة سنتات لحجم بيانات كهذا)، أو سكربت Node.js بحساب خدمة (Service Account) يقرأ المجموعات من القديم ويكتبها في الجديد.
   - **حسابات الموظفين** لا تنتقل بكلمات مرورها؛ تُنشأ من جديد. مع ملاحظة أن معرفات المستخدمين (uid) ستتغير، فيجب تحديث `trainerId` في الدورات والتسجيلات والحضور (أسهل طريقة: بعد إنشاء حسابات المدربين الجديدة، افتح كل دورة وأعد اختيار مدربها وحفظها؛ النظام يحدّث التسجيلات والحضور تلقائيا).

**الانتقال لاستضافة أخرى غير Firebase Hosting:** ناتج `npm run build` مجلد `dist` من ملفات ثابتة يمكن رفعه على أي استضافة (Netlify، Vercel، Cloudflare Pages...)، مع شرط توجيه كل المسارات إلى `index.html`. قاعدة البيانات تبقى على Firebase. أضف نطاق الاستضافة الجديدة في Firebase Console ← Authentication ← Settings ← Authorized domains.

**الانتقال بعيدا عن Firebase بالكامل:** يتطلب إعادة كتابة `src/lib/` (firebase، store، api، auth) وتحويل `firestore.rules` إلى صلاحيات في الخادم الجديد. الواجهة (`views/`، `ui.tsx`) والتصدير والتنسيق تبقى كما هي تقريبا.

## 22. النسخ الاحتياطي

الخطة المجانية لا تتيح نسخا احتياطيا تلقائيا. ما هو متاح حاليا:

- **دوريا (يدوي):** تصدير كشف الطلاب وكشوف الدورات (المالي والحضور) Excel وحفظها في مكان آمن، مثلا نهاية كل دورة وكل شهر.
- **مقترح تطوير مستقبلي:** زر "تنزيل نسخة احتياطية" للإدارة يصدّر كل المجموعات في ملف JSON واحد، وزر استعادة. يمكن إضافته دون تكلفة.
- **إن تمت الترقية لخطة Blaze:** تفعيل Point-in-time recovery أو الجدولة اليومية للنسخ الاحتياطي من Firestore ← Backups.

Firestore نفسه موثوق ومكرر على خوادم Google؛ الخطر الحقيقي هو الحذف الخاطئ من داخل النظام، ولهذا الحذف مقصور على الإدارة ونائب المدير، وحذف الطالب ممنوع إذا كان مسجلا في دورة.

## 24. تسليم النظام لمبرمج

أرسل له:
1. رابط المستودع أو أضفه كمتعاون (GitHub ← Settings ← Collaborators).
2. هذا الملف `docs/SYSTEM.md`.
3. إن احتاج الوصول لـ Firebase: أضفه من Firebase Console ← Project settings ← Users and permissions، **بأقل صلاحية تكفي** (Viewer للاطلاع، Editor للنشر)، وأزله بعد انتهاء العمل.

**ما يجب أن يعرفه المبرمج بسرعة:**
- React + TypeScript + Vite + Tailwind 4، بدون خادم؛ Firebase Auth + Firestore + Hosting على خطة Spark.
- كل الكتابات في `src/lib/api.ts`، وكل القراءات عبر `useCollection` / `useDocument` في `src/lib/store.ts` (اشتراكات لحظية مشتركة).
- الصلاحيات مزدوجة: `roles.ts` للواجهة و`firestore.rules` للحماية الفعلية. يجب أن يبقيا متطابقين.
- `enrollments` و`accounts` يتشاركان نفس المعرف؛ الفصل مقصود لإخفاء المال عن المدرب.
- الحضور مستند لكل يوم: `attendance/{courseId}_{day}` بخريطة `marks`.
- حقول منسوخة (studentName، studentPhone، trainerId، courseName) تُحدّث تلقائيا في `saveStudent` و`saveCourse`؛ أي مكان جديد يغيّر هذه البيانات يجب أن يحافظ على ذلك.
- للتجربة استخدم المحاكي (`VITE_EMULATOR=1`)، لا البيانات الحقيقية.
- لا تغيّر `USER_DOMAIN` في `firebaseConfig.ts`.
- لا مكتبة أيقونات عمدا (طلب الإدارة).

**طلبات تتطلب ترقية الخطة أو خادما** (للعلم قبل الوعد بها): إعادة تعيين كلمة مرور موظف من النظام، حذف حساب موظف من النظام، إرسال رسائل SMS أو واتساب أو بريد تلقائيا، نسخ احتياطي مجدول تلقائيا.
